# Viber Desktop: дослідження UI (фаза 2, варіант «сповіщення + OCR»)

Viber Desktop 27.3.0.2 у контейнері (Xvfb 1280x800). `viber.db` зашифрована, дерево AT-SPI не містить
списку чатів, заголовка й повідомлень (див. `viber-db-schema.md`). Інструмент — `viber-bridge/tools/lab.py`
(через `ops/viber-lab`). Дата: 2026-10-19.

## Розкладка вікна (1280x800)

| Зона | Координати | Примітка |
|------|------------|----------|
| Список чатів | x 0–300 | AT-SPI: `filler` без дітей |
| Заголовок чату | `300,62 790x72` | ім'я / статус або «Unknown» + номер; кнопки дзвінків праворуч на y≈86 |
| Повідомлення | `300,134 980x589` | |
| Поле введення | `452,742` (ширина 460 з бічною панеллю, 760 без) | AT-SPI `text [editable]`, єдине поле крім пошуку |
| Пошук | `104,40` | AT-SPI `text [editable]`, desc 9 символів, видно завжди |

`Escape` закриває бічну панель, але не чат.

## Відправка: перевірка адресата (замість `verify_target` по viber.db)

Перевірено на живому Viber:

1. Deep link на фіктивний `+380000000000` → екран «Unknown isn't on Viber yet», кнопка `Viber Out`,
   **поля введення немає**, у заголовку `Unknown` + `+380000000000` (OCR розпізнає). Це «нейтральний стан».
2. Deep link на номер у Viber → **поле введення з'являється**.
3. Номер не у Viber → те саме, що п. 1 (немає поля, є `Viber Out`) → `not_found`.

Правило: перед кожною відправкою — нейтральний стан (перевірити: поля введення немає, у заголовку нулі);
потім deep link клієнта; вставляти лише якщо поле введення з'явилося й заголовок уже не нейтральний.
Поле може з'явитися лише в чаті, який відкрило наше посилання, тож текст не потрапить у попередній чат.

Заголовок: незбережений контакт — номер (можна звірити з цільовим), збережений у телефоні — ім'я і статус
(номера немає, звірка неможлива; захищає лише нейтральний стан).

OCR (tesseract ukr+eng) тексту повідомлень помиляється («це» → «we») — для вмісту не придатний,
для цифр номера в заголовку працює.

## Вхідні: сповіщення D-Bus

Viber шле `org.freedesktop.Notifications.Notify`, якщо:
- сервер сповіщень **уже був на шині, коли Viber стартував** (інакше Viber не шле нічого до перезапуску);
- вікно Viber **не активне** (згорнуте). З активним вікном сповіщень немає.

Поля (`app_name='ViberPC'`):

| Поле | Вміст |
|------|-------|
| `summary` | ім'я контакту, як збережено в телефоні магазину (для незбережених — очікуємо номер, **не перевірено**) |
| `body` | повний текст (перевірено 107 символів без обрізання); фото → 13 символів без підпису (ймовірно `Photo message`) |
| `actions` | `['default', ...]` — клік по сповіщенню |
| `hints` | `category`, `desktop-entry`, `image-path` (аватар), `urgency` |

Відкриті питання:
- `summary` для номера, якого немає в контактах телефону магазину (чи там номер).
- Чи відкриває `ActionInvoked(id, "default")` відповідний чат (тоді можна дочитати заголовок).
- Як зіставити ім'я збереженого контакту з номером.
- Кілька повідомлень поспіль: окреме сповіщення на кожне чи `replaces_id`.
- Чи шле Viber сповіщення, коли вікно згорнуте, а міст щойно відкривав чат для відправки.
