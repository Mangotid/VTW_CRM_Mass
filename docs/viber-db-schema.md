# Схема `viber.db` (Viber Desktop)

> **Статус (2026-10-19): `viber.db` зашифрована** у Viber Desktop 27.3.0.2 — перші 16 байтів випадкові, не
> `SQLite format 3`; `sqlite3`: `file is not a database`. Поруч незашифровані `data.db` (36 КБ) і `~/.ViberPC/config.db`.
> Розшифровувати не будемо (обхід захисту Viber, ризик для акаунта, ламається з оновленнями).
> Власник погодив дослідження читання UI через AT-SPI: `viber-bridge/tools/atspi_dump.py`.
> Нижче — початковий план для незашифрованої бази, залишено для довідки.

## Як знімати (лише читання)

Усе — всередині контейнера, база відкривається лише для читання. Реальні тексти, імена й номери
**не копіювати** в цей файл: у прикладах рядків замінювати на `<text>`, `<name>`, `+380XXXXXXX12`.

```bash
docker compose exec viber-bridge bash -c 'ls ~/.ViberPC/'
DB='/home/viber/.ViberPC/<account>/viber.db'
docker compose exec viber-bridge sqlite3 -readonly "$DB" '.tables'
docker compose exec viber-bridge sqlite3 -readonly "$DB" '.schema'
docker compose exec viber-bridge sqlite3 -readonly "$DB" 'PRAGMA journal_mode;'
# Приклади рядків — після тестового обміну з власним номером, без даних клієнтів:
docker compose exec viber-bridge sqlite3 -readonly -header "$DB" 'SELECT * FROM <table> ORDER BY <id> DESC LIMIT 5;'
```

Тестовий сценарій: з особистого телефону написати на корпоративний номер (вхідне), відповісти з
Viber Desktop (вихідне), надіслати фото (вкладення), написати новому контакту через deep link.

| Як відрізнити приватний чат від групи / спільноти | |
